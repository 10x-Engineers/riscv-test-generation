Making the library compile against the real model

Seven files, four unrelated reasons. This is the commit that took the symbolic engine from "does not build" to "runs the RISC-V model".

FileWhy it had to change
isla-sail/jib_ir.ml
isla-sail/sail_plugin_isla.ml		 Upstream Sail API drift. Jib.funtype's bool tag became a variant, CT_bit was removed, and the rewrite-pass list had gained, lost and reordered entries. isla-sail is a Sail plugin, so it must track whatever the Sail it links against looks like.
isla-lib/src/primop.rs Primops the model calls that the library never implemented: cancel_reservation, valid_reservation, match_reservation, load_reservation, count_trailing_zeros, vector_init, sys_enable_experimental_extensions.
isla-lib/src/bitvector.rs
bitvector/b64.rs, b129.rs		 BV::trailing_zeros, required by the new primop.
isla-lib/src/memory.rs check_concrete_overlap hardcoded 64-bit addresses. RV32 addresses are 32 bits, so reads were silently mis-sized. Now uses the address's own solver-tracked width.
The one that mattered most. vector_access and vector_update had no case for struct-typed elements, because smt_value cannot represent Val::Struct. RISC-V's PMP configuration is vector(64, Pmpcfg_ent) — a vector of bitfield structs, not bitvectors — so any symbolic access to a PMP register crashed the engine. The fix builds a per-field ITE instead. Without it there is no symbolic PMP testing at all, and PMP is a required item in the RFP.

16 July 2026 · sail-riscv

The model side: entry points and a codegen workaround

The generator needs a two-phase init/step calling convention, which the model did not expose. isla_testgen_init() and isla_testgen_step() were added to main.sail, modelled on the existing isla_footprint entry points, and fetch() was made non-private so the latter could call it.

Then a compiler bug got in the way. Any Sail function binding _ or a destructuring pattern to a parameter of two or more tuple elements got two inconsistent synthetic names out of isla-sail. Worked around by destructuring in the function body instead of the parameter list — about 50 functions across core/, sys/, extensions/ and pmp/.

Four functions hit the same bug in the scattered-function merging step rather than in any clause body, so read_CSR, write_CSR, is_CSR_accessible and is_CSR_exception_virtual — 302 function clauses across ~17 files — were fully de-scattered into one plain function each, preserving first-match-wins order.

reset_pmp() also had to build a fully concrete Mk_Pmpcfg_ent(zeros()) per entry rather than a with-update on the prior symbolic value. Together with the vector_access fix above, this is what unblocked PMP.

16 July 2026 · isla-testgen

The RISC-V target itself

The generator is organised around a Target trait of some 28 methods — register naming, PC alignment, entry points, ELF emission. Adding RISC-V meant implementing it, writing an object emitter, and fixing three assumptions in the shared execution engine that were true only for the architectures already supported.

FileWhat it does
src/target.rsthe RiscV Target implementation
src/generate_object_riscv.rsELF emitter, 405 lines
src/execution.rsthree generic fixes — see below
riscv-ir/riscv32.irthe compiled model IR, 451,420 lines
Three assumptions that were not portable.

Concrete boot PC. The engine set the initial PC by asserting equality at the solver level. That silently does nothing when the PC is already concrete — which it is, because RISC-V's init calls reset(). The frame kept the wrong PC. Now the value is overwritten directly, which works whether it was symbolic or concrete.

PC width vs address width. RV32's PC is 32 bits, but the model's sail_mem_read interface uses 64-bit addresses regardless of XLEN. The PC is now zero-extended to addr_size() for the fetch.

Register numbering. GPRs were assumed to start at zero. RISC-V's x0 is hardwired to zero and is not a general-purpose register, so a first_gpr_index() was added to the trait.

11 August 2026

Privileged capability, and making the repo clonable

Per-ELF coverage, PMA scenarios driven by the model's own config, and interrupt delivery. Separately, paths.py replaces absolute paths that had been repeated across four scripts, and the model becomes a submodule.

Two things the model taught us here. --pending-interrupt deliberately left mstatus.MIE clear, so it tested WFI rather than delivery. Adding --deliver-interrupt exposed that delegation had to use a supervisor software interrupt: legalize_mideleg hardwires the machine-mode bits to zero, so delegating a machine software interrupt writes 0 and the trap is still taken in M-mode. The first version did exactly that and read as a delegation failure when it was an impossible test.

Three of the five repositories are forks, and every change in them was made to reach the RISC-V model rather than to alter what those tools do. The changes divide cleanly into four kinds: API drift in the Sail plugin, missing primops the model calls, portability assumptions that were true only for 64-bit zero-based-GPR targets, and one genuine engine gap — struct-typed vector elements — without which PMP could not be tested symbolically at all.

The model fork is the one worth being precise about. It carries a single commit, and nothing in it changes architectural behaviour: two entry points, a workaround for an isla-sail codegen bug affecting roughly 50 functions, four scattered functions consolidated, and one initialisation made concrete. But they are changes, which is why the technical plan does not describe the model as unmodified.
