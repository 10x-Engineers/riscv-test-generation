RISC-V Sail test generation · overview

Sail Model to Coverage Report

Six stages in a closed loop. Coverage is not only a report — it is the feedback that drives generation of tests for what is still missing.

Coverage: what “100%” means

Every target in the configuration's reachable denominator has at least one generated test, and every excluded target is recorded with a reason. It is a statement about the target list — not about Sail source branches, and not about differential agreement.
Reachable coverage  Does every reachable target have a test?
Model source coverage  Which Sail source branches were exercised?
Fault sensitivity  Can each test fail — proven by a passing and a deliberately broken run?
Differential agreement  Does a simulator not derived from the model agree?

Reported separately, never combined. One number cannot distinguish what was reached from whether the tests could detect a fault.

How the privileged architecture is reached

The model implements the entire privileged architecture through nine instructions. Coverage therefore comes from machine state the preamble builds, not from opcode selection — which is what makes 29 extensions and capabilities reachable at all.
