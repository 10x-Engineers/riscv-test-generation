Upstream, used unchanged

extract_state.rs needed no RISC-V work at all. It is 1 of the 5 files in isla-testgen/src/ the pipeline touches, and it is not in the diff. The stage that turns a solved SMT model into concrete registers and memory was already architecture-neutral — which is a small piece of evidence that the seam upstream chose was the right one, and part of why a new target could be added additively.

The three fixes in execution.rs

This is the only place we rewrote someone else's working code, so it is worth spelling out.

FixWhat was wrongWhat it does now
Setting the start PC The old code asked the solver to agree that the PC equals the start address. If the PC is already a fixed number, that does nothing at all — and ours is fixed, because our init calls the model's own reset(), which sets a real boot PC. The test then began from the wrong address, quietly Writes the value straight in. Works whether the old value was fixed or still symbolic
Fetching on RV32 The model's memory interface uses 64-bit addresses whatever XLEN is. On RV32 the PC is 32 bits, so the fetch address was the wrong width Widens the PC to the memory's address width before the read, and hands the natural-width PC back to callers unchanged
Picking scratch registers The free-register list started at register 0 and included registers the harness itself needs Counts from the target's own first register index, then removes anything the harness reserves

elsewhere		 About 205 CSR clauses, scattered across 17 files, consolidated by hand into three plain functions with an explicit match Two real reasons. Sail's scattered-clause merging synthesises a tuple for any merged function with two or more parameters, and isla-sail miscompiles it. And a consolidated read_CSR lets the solver take a fixed CSR address straight to one arm instead of joining paths — which is what unblocked PMP CSR reads. A pattern worth naming. Five of these changes — the CSR consolidation, core/callbacks.sail, pmp/pmp_control.sail, reset_pmp(), and primop.rs — are not RISC-V work at all. They are places where the model uses a Sail feature the symbolic tooling could not yet handle. Each was fixed on whichever side was cheaper and least invasive, and every one is written up in the code where the next person will hit it. That is the real shape of “making the Golden Model symbolically executable”: mostly not new features, mostly closing gaps between two existing tools.
